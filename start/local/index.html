Start here: native preview in about 10 minutes

Download ocp-native-v0.1.1-preview.1.zip and SHA256SUMS from the v0.1.1-preview.1 prerelease into one folder. Python 3.12 on macOS or Linux is required; check python3.12 --version first. No Git, Node, source build, key or model call is needed for Python/MCP. Dependencies download from public PyPI. Ten minutes is an estimate after Python is installed, not a measured external-user success rate.

1. Verify your download

Calculate the native ZIP checksum
shasum -a 256 ocp-native-v0.1.1-preview.1.zip

Compare with the native ZIP line in SHA256SUMS; stop if they differ. On Linux, sha256sum is also available. Checksums detect changed bytes, not publisher identity.

2. Install, calculate and print MCP configuration

Use a new extraction folder.

Install and run the native preview
unzip ocp-native-v0.1.1-preview.1.zip -d ocp-native-preview
cd ocp-native-preview
python3.12 -B install.py
.native/bin/python -I -B demo.py
.native/bin/python -I -B mcp_config.py

Expect PASS, three actual jobs, zero model calls, and independently checked costs: routing 18 meters, worker 7 cost units, inventory 16 cost units. The routing result is feasible; the small planning examples have checked optimality proofs. Add the printed configuration to the MCP host on this same machine and reload it; configuration generation does not establish LLM acceptance.

3. Apply your own problem

Stay in the kit. Read WORKED_EXAMPLES.md for input changes, PROJECT_GUIDE.md for an independent app, BYO_WORKER.md for engine replacement or PROFILE_EXTENSION.md for another problem. Reuse an existing .native environment; after moving the kit, reinstall into a new environment and regenerate configuration.

Optional Node correction for the first ZIP: its bundled README omits .review.1 in the archive names. Use the corrected Node installation command. Python/MCP are unaffected.

Core 0.1 from source

1. Prepare your machine

Use Git and Python 3.12 on PATH; no Node/npm are needed for this path. Public-source CI runs Python/Node on macOS arm64 and native Linux x64 for the exact checked commit. Windows installation and native Linux arm64 remain unverified. The installer rejects Windows.

2. Build and install

Run both blocks in the same terminal. Public PyPI dependencies are downloaded. The setup command runs two real routing engines and checks both results, plus deliberate invalid inputs and outputs.

Clone the public source
git clone https://github.com/omelet-ai/optimization-context-protocol.git
cd optimization-context-protocol
Build, install, solve and independently check
OCP_WORK="$(mktemp -d)"
python3.12 -B tools/quickstart.py --directory "$OCP_WORK"
cd "$OCP_WORK/kit"

start.py and sample files are generated inside the kit. Keep the terminal there. For a lasting installation, replace mktemp -d with a new directory outside the checkout and retain it. To rerun without reinstalling, use .agent/bin/python -B demo.py --diagnostics.

3. Solve three problems

Use the same app across three domains
.agent/bin/python -I -B multi_app.py --profile routing.basic --input basic-input.json --request-id first-routing
.agent/bin/python -I -B multi_app.py --profile worker.scheduling --input worker-input.json --request-id first-worker
.agent/bin/python -I -B multi_app.py --profile inventory.replenishment --input inventory-input.json --request-id first-inventory

Expected checked costs: 18 meter, 7 cost_unit and 16 cost_unit. Also inspect solution_found and response.status. PASS is a transcript check, not a guarantee of optimality.

Copy a sample before editing it and use a new request ID for changed input. See changes with known answers and supported limits.

Troubleshooting

If a sample is missing, change to the generated kit directory. If ENVIRONMENT_EXISTS appears, reuse its Python rather than reinstalling. If a dependency download fails, check public registry access. The README includes recovery steps.

Native v1 from public source

Use this opt-in path for actual asynchronous jobs and the eight native MCP tools. Start in the repository root after the clone command above, using a new terminal if you already entered the Core kit. Python 3.12 is required; Python/MCP need no Node, Foundry checkout, account or key.

Build and run the native source preview
OCP_NATIVE_WORK="$(mktemp -d)"
python3.12 -m venv "$OCP_NATIVE_WORK/build-env"
"$OCP_NATIVE_WORK/build-env/bin/python" -m pip install -r tools/requirements-dev.lock
"$OCP_NATIVE_WORK/build-env/bin/python" -B tools/build_native_candidate.py --output "$OCP_NATIVE_WORK/kit"
cd "$OCP_NATIVE_WORK/kit"
python3.12 -B install.py
.native/bin/python -I -B demo.py

Expect PASS, three actual jobs and independently checked costs: routing 18 meters, worker scheduling 7 cost units and inventory 16 cost units. These scripts are generated kit files. Keep this terminal in the native kit directory; reuse its Python to rerun or choose a fresh output directory to rebuild.

Native MCP

Configure and exercise native MCP without calling a model
.native/bin/python -I -B mcp_config.py
.native/bin/python -I -B mcp_walkthrough.py --domain worker-scheduling --input worker-input.json

Configuration selects ocp_runtime.native_mcp and eight tools. For optional TypeScript, use Node 24/npm and add --with-typescript to the build command with a new output path. Use the prerelease ZIP or build native packages locally. Package registries are not open.

Apply a business problem

Use the inspection assignment guide for CSV input, real jobs, workload tables, scenario changes and independent checks. For a source-build-free start, download the v0.1.1-preview.1 native ZIP and SHA256SUMS, verify the checksum, then follow START_HERE.md in the ZIP.

Source CI checks macOS arm64 and native Linux x64 with Python/Node; offline Linux emulation is a separate rehearsal. This does not extend the immutable ZIP acceptance. Native Linux arm64 and Windows are unverified. Automated checks do not establish external-human or model-host acceptance.
