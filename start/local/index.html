OCP is an Apache-2.0 open-source developer preview. Start from the public source: no account, trial key or model call is required. Package registries and hosted trial enrollment are not open.

1. Prepare your machine

Use Git and Python 3.12 on PATH; no Node/npm are needed for this path. Full local regression is on macOS Apple Silicon; a limited Linux x86_64 container path was checked. Native Linux and Windows are not fully verified. The installer rejects Windows.

2. Build and install

Run both blocks in the same terminal. Public PyPI dependencies are downloaded. The setup command runs two real routing engines and checks both results, plus deliberate invalid inputs and outputs.

Clone the public source
git clone https://github.com/omelet-ai/optimization-context-protocol.git
cd optimization-context-protocol
Build, install, solve and independently check
OCP_WORK="$(mktemp -d)"
python3.12 -B tools/quickstart.py --directory "$OCP_WORK"
cd "$OCP_WORK/kit"

start.py and sample files are generated inside the kit. Keep the terminal there. For a lasting installation, replace mktemp -d with a new directory outside the checkout and retain it. To rerun without reinstalling, use .agent/bin/python -B demo.py --diagnostics.

3. Solve three problems

Use the same app across three domains
.agent/bin/python -I -B multi_app.py --profile routing.basic --input basic-input.json --request-id first-routing
.agent/bin/python -I -B multi_app.py --profile worker.scheduling --input worker-input.json --request-id first-worker
.agent/bin/python -I -B multi_app.py --profile inventory.replenishment --input inventory-input.json --request-id first-inventory

Expected checked costs: 18 meter, 7 cost_unit and 16 cost_unit. Also inspect solution_found and response.status. PASS is a transcript check, not a guarantee of optimality.

Copy a sample before editing it and use a new request ID for changed input. See changes with known answers and supported limits.

Troubleshooting

If a sample is missing, change to the generated kit directory. If ENVIRONMENT_EXISTS appears, reuse its Python rather than reinstalling. If a dependency download fails, check public registry access. The README includes recovery steps.

Native v1 from public source

Use this opt-in path for actual asynchronous jobs and the eight native MCP tools. Start in the repository root after the clone command above, using a new terminal if you already entered the Core kit. Python 3.12 is required; Python/MCP need no Node, Foundry checkout, account or key.

Build and run the native source preview
OCP_NATIVE_WORK="$(mktemp -d)"
python3.12 -m venv "$OCP_NATIVE_WORK/build-env"
"$OCP_NATIVE_WORK/build-env/bin/python" -m pip install -r tools/requirements-dev.lock
"$OCP_NATIVE_WORK/build-env/bin/python" -B tools/build_native_candidate.py --output "$OCP_NATIVE_WORK/kit"
cd "$OCP_NATIVE_WORK/kit"
python3.12 -B install.py
.native/bin/python -I -B demo.py

Expect PASS, three actual jobs and independently checked costs: routing 18 meters, worker scheduling 7 cost units and inventory 16 cost units. These scripts are generated kit files. Keep this terminal in the native kit directory; reuse its Python to rerun or choose a fresh output directory to rebuild.

Native MCP

Configure and exercise native MCP without calling a model
.native/bin/python -I -B mcp_config.py
.native/bin/python -I -B mcp_walkthrough.py --domain worker-scheduling --input worker-input.json

Configuration selects ocp_runtime.native_mcp and eight tools. For optional TypeScript, use Node 24/npm and add --with-typescript to the build command with a new output path. Native packages are built locally; registry and prebuilt downloads are not offered.

Verified on macOS arm64 and in a network-disabled Linux amd64 Python 3.12 container under Docker on an arm64 host. Native Linux arm64 and Windows are unverified. Automated checks do not establish external-human or model-host acceptance.
