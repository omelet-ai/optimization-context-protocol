MCP: provide context before solving

Example request: “Reduce delivery distance while respecting vehicle capacity.”

  1. Discover the context. Call ocp_context(), choose an advertised profile, and inspect its input schema and request template.
  2. Resolve missing data. Ask for vehicle capacity or missing distances. Do not invent values or silently omit constraints.
  3. Validate, then execute. Reject unsupported requirements before making a solve call.
  4. Evaluate and explain. Evaluate a returned solution, run a separate checker, and report the actual status, cost and verification scope. Preserve unknown and unevaluated values.

OCP defines optimization request and result semantics. Its optional MCP binding exposes that context and those operations to an AI host. Python and HTTP applications can use OCP without MCP.

This is a recommended agent workflow, not a recorded model conversation. Local server and smoke checks do not establish correct behavior for every model or host. Provider evaluation and independent verification are separate steps.

Inspect and configure the local MCP server
.agent/bin/python -I -B local_agent.py doctor --profile all
.agent/bin/python -I -B local_agent.py smoke --input basic-input.json --request-id first-mcp
.agent/bin/python -I -B local_agent.py config --profile all --format json
.agent/bin/python -I -B local_agent.py config --profile all --format codex

Doctor discovers six tools and checks all three profile contexts with zero solve calls. Smoke executes one real routing problem and independently checks cost 18. Config prints JSON or Codex TOML with absolute paths; it does not change host settings. Install on the machine where your MCP host runs, review the output, add it to that host, and reload its MCP configuration.

Start the agent with ocp_context(); inspect the input schema and request template, ask for missing values, then validate before execution. Preserve feasible versus optimal, timeout versus infeasible, and null versus zero. These local commands make no model calls. Host/model usage has separate limits and costs. Read host setup and troubleshooting.

Show exactly what was verified

Read the verification report beside the legacy measurement. Feasibility, cost recomputation, optimality and infeasibility have separate statuses. PARTIAL or INCOMPLETE never establishes an untested proof claim. Offline checking cannot attest engine execution.

Native v1: a separate app and MCP binding

Build this source preview with the native installation guide. The Core installation and six tools above remain a separate path. Native Python imports NativeClient from ocp_candidate.native; Node imports createOptimizationApiClient from ocp-candidate/native. Existing root imports remain Core 0.1.

The candidate MCP entrypoint is ocp_runtime.native_mcp. Its eight tools use actual jobs and explicit domain selection. Start with ocp_native_context; use advertised selectionTemplate and requestTemplate, ask for missing data, and never invent a payload.

Native candidate tools — installed by the native source quickstart
ToolPurpose
ocp_native_contextList domains or read the selected catalog, schemas and templates.
ocp_native_requirementsResolve configuration and input requirements without solving.
ocp_native_validateValidate the declared problem body; invalid input is not infeasibility.
ocp_native_submitSubmit real work with an explicit idempotency key; return a job.
ocp_native_jobPoll job state; succeeded does not prove optimality.
ocp_native_resultFetch the completed domain result with its original mathematical meaning.
ocp_native_cancelRequest cancellation, then confirm a terminal job state.
ocp_native_evaluateEvaluate a returned solution; independent checking is separate.

Keep credentials and tenant in trusted host configuration, not tool arguments. Retain the original input and idempotency key after uncertainty. Submitting a job, receiving a result, provider evaluation and independent verification are separate steps. This local binding does not claim the full gateway/ocps1 state profile or acceptance by every model/host.
