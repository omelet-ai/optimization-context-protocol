Core 0.1과 native v1

두 경로 모두 공개 소스 개발자 프리뷰입니다. Native v1은 명시적으로 선택하는 binding을 Foundry Capability Contract v1에 맞춥니다. 구현·선정된 공통 계약·빌드 도구는 공개 저장소에 있습니다. native 프리릴리스 ZIP 다운로드 또는 로컬 빌드. 패키지 레지스트리에는 아직 게시하지 않았습니다.

두 계약 계층, 명시적인 버전

Native 외부 catalog/job/error는 contractVersion: "1"을 사용합니다. 참조 문제는 domainPayloadFormat: "ocp-core-request/0.1.0"을 선언하고, JobResult.result 는 원래 Core 결과를 유지합니다. 내부 동기 실행 프로파일은 솔버 호출을 설명하며 외부 작업 수명주기는 비동기입니다. 계약·도메인 프로파일·패키지 버전은 서로 다른 대상을 가리킵니다.

행렬 라우팅이 좌표 라우팅이 되거나 작업자 배정이 간호사 스케줄링이 되지는 않습니다. 일치하는 도메인 프로파일·단위·비용·제약만 비교하세요.

작업 제출부터 검산된 결과까지

  1. 정확한 카탈로그·요청 템플릿을 조회하고 요구사항을 확인한 뒤 입력을 검증합니다.
  2. 작업을 제출하고 작업 ID·입력·멱등 키를 보관합니다.
  3. queued/running 작업이 종료 상태에 도달할 때까지 조회한 뒤 결과를 가져옵니다.
  4. 도메인 상태를 확인하고 사용 가능한 해를 평가한 뒤 별도 checker로 독립 검산합니다.

succeeded 는 계산 완료를 뜻하며 수학적 최적성을 뜻하지 않습니다. feasible/optimal/infeasible/unknown, 종료 이유, 증명, 미평가 null을 유지하세요. 응답이 불확실하면 같은 멱등 키와 입력을 재사용합니다. 취소는 요청이므로 계산이 멈췄다고 말하기 전에 작업의 종료 상태를 확인하세요. 시간 초과 메시지만으로 취소를 입증할 수 없습니다.

호환성과 참조 구현의 한계

기존 Core 0.1 import와 동기 의미는 계속 지원하며 제거 일정은 없습니다. Native 클라이언트는 명시적 진입점과 로컬에서 빌드한 native kit를 선택합니다. 기본 통신 형식을 바꾸려면 버전별 migration과 소비자 검사가 필요합니다.

Native MCP 후보는 상태를 보관하지 않는 로컬 binding입니다. 전체 foundry-ocp-standard/v1 gateway/ocps1 state 프로파일을 구현한 것은 아닙니다. 이 참조 구현은 compilation·repair·ocps1 state를 지원 기능으로 선언하지 않습니다. localhost 접근, 2시간 휘발성 기록, 기본 세션당 128개 작업 한도는 로컬 참조 정책이며 범용 프로토콜 요구사항이 아닙니다. 인증정보와 tenant는 신뢰하는 호스트 설정입니다.

네 가지 계층

Core: 지원 기능·요구사항·요청·검증·결과·실패·평가. 도메인·실행 프로파일: 단위·제약·목적·실행 보장. Binding: 라이브러리·HTTP·MCP. 환경 정책: 신원·한도·만료·서비스 접근.

이 한도는 현재 프로파일 계약에 속하며 OCP Core 전체의 범용 규모 한도가 아닙니다. 구현은 더 좁을 수 있습니다. 라우팅 교육용 엔진은 최대 방문 6개·차량 3대만 지원합니다. 요청을 만들기 전에 선택한 엔진의 지원 기능을 조회하세요.

모두 지원 범위가 명시된 버전 0.1.0 개발자 프리뷰 계약입니다. routing.coordinates 는 Haversine/ceil을 사용하는 별도 좌표 프로파일입니다. assignment.fixture 는 솔버 없이 스키마·witness fixture만 제공합니다.
