OCP는 Apache-2.0 오픈소스 개발자 프리뷰입니다. native ZIP으로 시작하거나 개발용 소스 빌드를 선택하세요. 계정·trial 키·모델 호출은 필요 없습니다. 패키지 레지스트리와 호스팅 trial 가입은 아직 열리지 않았습니다.

여기서 시작: 약 10분 native 프리뷰

파일 ocp-native-v0.1.1-preview.1.zip 및 SHA256SUMS 을 v0.1.1-preview.1 프리릴리스 에서 한 폴더로 내려받으세요. macOS 또는 Linux의 Python 3.12가 필요합니다. 먼저 python3.12 --version 을 확인하세요. Python/MCP에는 Git·Node·소스 빌드·키·모델 호출이 필요 없습니다. 의존성은 공개 PyPI에서 설치합니다. 10분은 Python 설치 후 예상 시간이며 측정된 외부 사용자 성공률이 아닙니다.

1. 다운로드 검증

native ZIP 체크섬 계산
shasum -a 256 ocp-native-v0.1.1-preview.1.zip

SHA256SUMS의 native ZIP 항목과 비교하고, 다르면 중단하세요. Linux에서는 sha256sum 도 사용할 수 있습니다. 체크섬은 파일 변경을 감지하며 게시자의 신원을 증명하지는 않습니다.

2. 설치·계산·MCP 설정 출력

새 폴더에 압축을 해제하세요.

native 프리뷰 설치·실행
unzip ocp-native-v0.1.1-preview.1.zip -d ocp-native-preview
cd ocp-native-preview
python3.12 -B install.py
.native/bin/python -I -B demo.py
.native/bin/python -I -B mcp_config.py

PASS, 실제 작업 3개, 모델 호출 0회와 독립 검산된 비용(라우팅 18미터·작업자 7비용 단위·재고 16비용 단위)을 확인하세요. 라우팅 결과는 실행 가능한 해이며, 작은 계획 예제들은 최적성 증명까지 검사합니다. 같은 컴퓨터의 MCP 호스트에 출력된 설정을 추가하고 다시 불러오세요. 설정 생성만으로 LLM 수락이 검증되지는 않습니다.

3. 내 문제에 적용하기

kit 폴더에서 안내 파일을 확인하세요. WORKED_EXAMPLES.md 는 입력 변경, PROJECT_GUIDE.md 는 독립 앱, BYO_WORKER.md 는 엔진 교체, PROFILE_EXTENSION.md 는 다른 문제 유형을 설명합니다. 기존 .native 환경을 재사용하세요. kit를 옮겼다면 새 환경에 재설치하고 설정을 다시 생성하세요.

첫 ZIP의 선택적 Node 안내 정정: 동봉 README의 압축파일 이름에는 .review.1 이 빠져 있습니다. 다음 정정된 Node 설치 명령을 사용하세요. Python/MCP에는 영향이 없습니다.

릴리스·소스 지원 범위 →

소스에서 Core 0.1 설치

1. 실행 환경 준비

PATH에 Git과 Python 3.12를 준비하세요. 이 경로에는 Node/npm이 필요 없습니다. 공개 소스 CI는 해당 커밋의 Python/Node를 macOS arm64와 native Linux x64에서 검사합니다. Windows 설치와 native Linux arm64는 미검증이며 설치 프로그램은 Windows를 거절합니다.

2. 빌드·설치

두 명령 블록을 같은 터미널에서 실행하세요. 의존성은 공개 PyPI에서 내려받습니다. 설치 명령은 실제 라우팅 엔진 두 개를 실행해 결과를 검산하고, 의도적으로 잘못된 입력과 출력도 검사합니다.

공개 소스 복제
git clone https://github.com/omelet-ai/optimization-context-protocol.git
cd optimization-context-protocol
빌드·설치·계산·독립 검산
OCP_WORK="$(mktemp -d)"
python3.12 -B tools/quickstart.py --directory "$OCP_WORK"
cd "$OCP_WORK/kit"

start.py 와 예제 파일은 kit 안에 생성됩니다. 해당 폴더에서 계속 진행하세요. 설치를 유지하려면 mktemp -d 를 checkout 밖의 새 폴더로 바꾸고 보관하세요. 재설치 없이 다시 실행할 때는 다음 명령을 사용합니다: .agent/bin/python -B demo.py --diagnostics.

3. 세 가지 문제 풀기

같은 앱으로 세 도메인 실행
.agent/bin/python -I -B multi_app.py --profile routing.basic --input basic-input.json --request-id first-routing
.agent/bin/python -I -B multi_app.py --profile worker.scheduling --input worker-input.json --request-id first-worker
.agent/bin/python -I -B multi_app.py --profile inventory.replenishment --input inventory-input.json --request-id first-inventory

예상 검산 비용은 18 meter, 7 cost_unit, 16 cost_unit입니다. 함께 확인할 필드: solution_found 및 response.status. PASS는 실행 기록 검사 결과이며 최적성 보장이 아닙니다.

예제는 복사해서 수정하고, 입력을 바꾸면 새 요청 ID를 사용하세요. 정답을 아는 입력 변경과 지원 한도 보기.

문제 해결

예제 파일이 없다면 생성된 kit 폴더로 이동하세요. ENVIRONMENT_EXISTS 오류가 나오면 재설치하지 말고 기존 Python을 사용하세요. 의존성 다운로드가 실패하면 공개 레지스트리 접근을 확인하세요. 복구 절차는 README에서 확인하세요.

공개 소스에서 native v1 설치

실제 비동기 작업과 native MCP 도구 8개를 사용할 때 선택하는 경로입니다. 위의 clone 명령 후 저장소 루트에서 시작하세요. 이미 Core kit로 이동했다면 새 터미널을 사용합니다. Python 3.12가 필요하며 Python/MCP에는 Node·Foundry checkout·계정·키가 필요 없습니다.

native 소스 프리뷰 빌드·실행
OCP_NATIVE_WORK="$(mktemp -d)"
python3.12 -m venv "$OCP_NATIVE_WORK/build-env"
"$OCP_NATIVE_WORK/build-env/bin/python" -m pip install -r tools/requirements-dev.lock
"$OCP_NATIVE_WORK/build-env/bin/python" -B tools/build_native_candidate.py --output "$OCP_NATIVE_WORK/kit"
cd "$OCP_NATIVE_WORK/kit"
python3.12 -B install.py
.native/bin/python -I -B demo.py

PASS, 실제 작업 3개와 독립 검산된 비용(라우팅 18미터·작업자 7비용 단위·재고 16비용 단위)을 확인하세요. 이 스크립트들은 kit에 생성되는 파일입니다. 터미널을 native kit 폴더에 두고 기존 Python으로 다시 실행하거나, 새 출력 폴더에 다시 빌드하세요.

Native MCP

모델 호출 없이 native MCP 설정·실행
.native/bin/python -I -B mcp_config.py
.native/bin/python -I -B mcp_walkthrough.py --domain worker-scheduling --input worker-input.json

설정은 ocp_runtime.native_mcp 와 도구 8개를 선택합니다. 선택적 TypeScript 경로는 Node 24/npm을 사용하고, 새 출력 경로를 지정한 빌드 명령에 --with-typescript 를 추가하세요. 프리릴리스 ZIP을 사용하거나 native 패키지를 로컬에서 빌드할 수 있습니다. 패키지 레지스트리는 아직 열리지 않았습니다.

업무 문제에 적용하기

다음 점검 작업 배정 안내 에서 CSV 입력·실제 작업·작업량 표·시나리오 변경·독립 검산을 확인하세요. 소스 빌드 없이 시작하려면 v0.1.1-preview.1 native ZIP과 SHA256SUMS를 내려받아 체크섬을 확인하고 ZIP의 START_HERE.md를 따르세요.

소스 CI는 macOS arm64와 native Linux x64의 Python/Node를 검사하며 오프라인 Linux 에뮬레이션은 별도 리허설입니다. 이 결과가 기존 ZIP의 검증 범위를 넓히지는 않습니다. Native Linux arm64와 Windows는 미검증입니다. 자동 검사는 실제 외부 사용자나 모델·호스트의 수락을 입증하지 않습니다.
