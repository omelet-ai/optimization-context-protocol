경로 A: 기존 프로파일 구현

엔진이 기존 프로파일의 의미를 지원할 때 선택하세요. 지원하는 교집합을 선언하고, 입력·출력을 명시적으로 연결한 뒤 반환된 결과를 검산합니다.

1. 교육용 엔진 실행

엔진 어댑터 실행·검산
.agent/bin/python -B byo_library.py basic-input.json --trace own-engine-trace.json
.agent/bin/python -B export_transcript.py --trace own-engine-trace.json --artifact byo_library.py --out own-engine-transcript.json
.agent/bin/python -B -m conformance.runner --bundle own-engine-transcript.json --artifact byo_library.py

2. 계산 구현 교체

함수 EnumeratingLibrary.solve(problem, time_limit_ms) 을 자체 구현으로 교체하세요. 유지해야 할 항목은 name, version 및 Outcome(solution, termination, objective) 결과입니다. 교육용 예제의 상한은 방문 6개·차량 3대입니다. 지원하지 않는 동작은 검증 단계에서 거절하세요.

3. 의미 선언·검사

라우팅은 명시적인 정수 미터 거리와 kg 적재량을 사용합니다. 엔진 교체는 프로파일·단위·비용·제약의 교집합 안에서만 유효합니다. 시간 초과를 불가능으로, 증명 없는 실행 가능한 해를 최적해로 표시하지 마세요. 변경 후에는 새 추적 기록을 생성하며 기존 기록은 덮어쓰지 않습니다.

경로 B: 새 문제 프로파일 정의

생산 스케줄링처럼 다른 문제를 다룬다면 라우팅 계산 함수만 바꾸는 것으로는 충분하지 않습니다.

  1. 프로파일 ID·버전, 입력·설정·해 스키마, 단위·목적·제약을 정의합니다.
  2. 결과와 실패의 의미, 실행 예산, 주장할 증명 범위를 명시합니다.
  3. 지원 기능 조회·요구사항 확인·검증·실행·평가를 구현합니다.
  4. 별도 checker, 정답을 아는 사례, 미지원 입력과 잘못된 결과에 대한 반례를 추가합니다.
  5. 실제 앱 소비자를 검사하고 호환성과 버전 변경을 문서화합니다. 이 검사가 준비되기 전에는 적합성이나 교환성을 주장하지 마세요.

작업자·재고 계약을 별도 도메인의 예시로 참고하세요. 이는 저작 체크리스트이며 범용 프로파일 생성기를 제공하지는 않습니다.

Native v1 엔진 등록 — 로컬 후보

위 경로는 공개 Core 0.1 kit를 설명합니다. 별도 native 후보에서는 도메인 어댑터와 import 가능한 계산 함수를 공통 서버에 등록합니다. ReferenceDomain 는 선언된 Core 도메인 의미를 유지하고, Registration(domain, solve) 는 엔진을 연결하며, LocalAPI 는 공통 작업 수명주기를 제공합니다. 별도 프로세스에서 실행할 계산 함수는 import 가능해야 하고, 실행용 Python 진입 스크립트에는 main guard가 필요합니다.

다음 native 저작 템플릿 은 공개 소스와 생성된 native kit에 포함됩니다. 새 문제에도 명시적인 스키마·의미·지원 기능·독립 검산이 필요합니다. 서버를 공유한다고 임의의 엔진을 서로 교체할 수 있는 것은 아닙니다.
