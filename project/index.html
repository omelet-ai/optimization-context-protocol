What is public?

Core 0.1, the native v1 source candidate and this documentation are public under Apache-2.0. The native source includes the selected shared contracts and portable build tools. Build a local kit using the native quickstart; prebuilt native downloads are not published. Existing Core imports remain supported. Package registries and public self-service trial signup are not open.

Why use OCP?

A direct solver API can be enough for one app. OCP adds a shared discovery, request, validation, result and checking boundary when another app, agent or compatible engine enters the picture. It does not promise arbitrary-engine interchangeability or universal industry coverage.

Current scope

Current 0.1.0 profile contracts
ProfileSupported problem and limitsOutside this profile
routing.basic1–64 visits, 1–16 vehicles; one depot; integer meter matrix and kg capacity.Time windows, multiple trips, optional visits and soft constraints.
worker.scheduling1–8 fixed-time tasks, 1–4 workers; availability, eligibility, overlap, workload and assignment cost.Shift generation, breaks, travel, overtime and fairness objectives.
inventory.replenishment1–4 independent products, 1–6 daily periods; given demand and lead time; order quantity ≤5 per product and period; capacity ≤50 items.Demand forecasting, shortages, shared storage or budgets, and uncertain demand.

These limits belong to the current profile contracts, not to OCP Core as a universal size limit. Implementations can be narrower: the routing teaching engine accepts at most 6 visits and 3 vehicles. Discover the selected engine’s capabilities before constructing a request.

Python/MCP/Node installation and examples are exercised automatically. This is bounded technical evidence, not unaided external developer acceptance, production certification or compatibility with every model/host.
